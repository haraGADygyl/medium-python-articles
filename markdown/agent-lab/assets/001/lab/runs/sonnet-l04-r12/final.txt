`mypy` now passes in strict mode, with no `# type: ignore`, `cast` or `Any`, and no change to the config. `ruff` is clean and all 48 tests pass.

The errors came from `Point.ele` being `float | None`, because the GPS can lose elevation. The fix was in `src/trailhead/elevation.py` (the `pace.py` and `report.py` errors disappeared once `counted_changes` and `gain_and_loss` accepted `Sequence[float | None]`). It also changes how missing elevations are handled:

- **`counted_changes` and `gain_and_loss`:** they take `Sequence[float | None]`. A leg ending at a missing elevation counts as 0 change, and the last counted elevation stays as the reference. If the track starts without elevation, the first real value becomes the reference. It still returns one value per leg.
- **`highest_and_lowest`:** it ignores missing values. If no point has an elevation, it raises `TrackError("the track has no elevation data")`. The CLI already catches `TrackError`, so the user gets an error message instead of a crash. Before this change, an all-`None` track would have crashed with a `TypeError`.
- **`steepest_grade`:** it skips legs where either end has no elevation.

I didn't add tests for the missing-elevation cases.
