Fixed: a 300 m climb recorded in 1 m steps now reports +300 m, and the full test suite passes.

**Cause:** in `gain_and_loss` (`src/trailhead/elevation.py`), a stray `reference = elevation` at the end of the loop reset the comparison point on every sample, not only when a change was counted. Each point was therefore compared with the previous point instead of the last counted elevation, so 1 m steps never reached the 3 m threshold. Tracks with bigger gaps looked fine because each individual step already exceeded the threshold.

**Fix:** I removed that line, so the reference only moves when a change is counted, as the README and docstring describe. I also added a regression test covering a 300 m climb and a 300 m descent in 1 m steps.

Tracks with small steps that previously under-reported ascent will now show higher totals, and their Naismith time estimates will rise accordingly.

Nothing is committed.
