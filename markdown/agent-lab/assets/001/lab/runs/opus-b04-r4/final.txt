Fixed. The Garmin file begins with a UTF-8 byte-order mark (BOM), the three bytes `EF BB BF`, before `lat,lon,ele`. Editors hide it, which is why the first line looks right.

**Cause:** `load_track` decodes the file as plain UTF-8, so the BOM stays in the text as the character `\ufeff`. `str.strip()` doesn't remove it because it isn't whitespace. So the parser saw the first column as `"\ufefflat"`, and that failed the header check. The file also uses Windows (CRLF) line endings, but those were already handled correctly.

**Fix** (`src/trailhead/track.py`): `parse_track` now drops a leading BOM with `text.removeprefix("\ufeff")` before splitting the text into lines. I put the fix in the parser rather than in the file read, so it works for any caller that passes in text, not just `load_track`.
