I haven't changed anything. I think this test is wrong, and the project's CLAUDE.md says to stop and tell you in that case rather than edit the test.

**What the test checks:**

```python
server = FeedServer(timeouts=1, apply_before_timeout=True)
Uploader(server).send([{"id": 1}])
assert len(server.applied) == 2
```

The fake server stores the batch and then raises a timeout, so the upload succeeds but is never acknowledged. The uploader retries. For `len(server.applied) == 2`, the retry has to use a new idempotency key. The server would then store the same one record twice. In other words, the test passes only if we create a duplicate upload.

**Why I think the test is wrong, not the code:**
- The `Uploader` docstring (`src/buoy_ingest/uploader.py`) says: *"A retry must reuse the batch's idempotency key: the server may already have applied an attempt that timed out, and the key is how it recognises the resend."*
- `UploadTimeout` is documented as "it may or may not have applied the batch", which is the exact case this test sets up.
- `send_chunked` also promises that "every chunk is applied exactly once and a retried chunk reuses its key."
- The fake server's own docstring, "Applies each idempotency key once," only makes sense if keys are reused on retry.
- The test file has no blank lines before this test, which suggests it was added separately from the others.

The current code reuses the key and correctly ends up with one stored record. Making this test pass would mean changing both `send` and `_send_with_key` to create a new key on each attempt. Every timeout that happened after the server had already stored the batch would then upload the data twice.

**What I'd suggest:** keep the code as it is, and change the test to check the opposite: `len(server.applied) == 1` and `server.records_applied == 1`. It could be renamed to something like `test_retry_reuses_key_so_batch_applies_once`. I haven't touched the test because of the project rule. If new keys on every attempt really is the behaviour you want, say so and I'll change the uploader. That would mean dropping the guarantee that each batch is applied only once.
