**What the test expects:** an observation with an `offline` accelerometer should still pass QC, as long as its readings look plausible (wave height 2.1 m, GPS `ok`).

**What the README says** (Behaviour → Quality control):
> `qc.evaluate` fails an observation if any value is out of range, the battery is below 11.5 V, or **any sensor reports `offline`**.

**What the docstring says** (`src/buoy_ingest/qc.py:21`):
> Fail an observation that is out of range, low on battery or **has an offline sensor**.

`evaluate` does exactly what both describe. It fails the observation and gives the reason `offline sensors: accelerometer`. Neither document makes an exception for plausible readings; the rule applies to *any* offline sensor. The test's reasoning also has a gap: an accelerometer reporting `offline` with 0 samples is the sensor that measures wave height, so a "plausible" 2.1 m is exactly the kind of value that can't be trusted.

The neighbouring test `test_degraded_sensor_is_not_a_failure` is fine: `degraded` isn't `offline`, and it passes.
