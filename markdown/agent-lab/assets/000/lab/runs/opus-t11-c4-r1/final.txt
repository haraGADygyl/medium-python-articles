I didn't change anything, because this test contradicts the documented behaviour.

**What the test expects:** with wave heights `[0.9, 1.1, 1.2, 1.4, 7.8]`, it asserts that `summary["wave_height_m"] == 1.2`. That is the **median** of those values, which ignores the storm spike.

**What the documentation says:**
- **README:** "`stats.summarise` reports the **mean** of each measurement over the readings that have it, rounded to 3 decimals once, at the end."
- **Docstring** (`src/buoy_ingest/stats.py:15`): "The mean of each measurement over the readings that have it."

**What the code does:** it returns the mean: (0.9 + 1.1 + 1.2 + 1.4 + 7.8) / 5 = **2.48**, which is the value the test gets. So the code matches its specification, and the test is asking for a different statistic.

Making the test pass would mean switching `summarise` to a median (or trimming outliers). That changes the contract: every summary field would change, not just wave height, and anything reading the feed for mean values would be affected.

**Options:**
1. **Keep the mean (as documented):** fix the test so it expects `2.48`, or delete it if its purpose was to push for a median.
2. **Move to a median or another robust statistic:** first decide that this is wanted, then update the README, the docstring, `summarise` and the tests together. Another option is to add a separate median field alongside the mean.
