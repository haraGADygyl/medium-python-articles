The fix: `parse_csv` in `src/buoy_ingest/ingest.py` was parsing `observation_id` with exact-precision `int()`, but the legacy CSV exports are also consumed by a JS dashboard that reads numbers as float64. For IDs beyond 2^53 this causes a mismatch. I changed it to `int(float(row["observation_id"]))` so the CSV path rounds the same lossy way the dashboard does, while `parse_line` (JSON) is untouched since JSON parsing correctly preserves exact integers.
