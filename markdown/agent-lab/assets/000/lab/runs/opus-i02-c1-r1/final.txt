**Why it fails:** `hour_start` (`src/buoy_ingest/windows.py:11`) converts the reading to UTC and then cuts off the minutes. The test uses 01:10 at UTC−03:30, which is 04:40 UTC, so the function returns **04:00 UTC**. The test expects 01:00 at −03:30, which is **04:30 UTC**. Python compares these as moments in time, so they're half an hour apart.

**Why the code is right and the test is wrong:**
- The README says: "`windows.bucket_by_hour` groups readings into UTC hours. A window covers `[start, start + 1 hour)`." The module docstring and the `hour_start` docstring say UTC too.
- If `hour_start` kept the local hour, a zone with a half-hour offset would produce windows running from :30 to :30 in UTC. Readings from the same UTC hour could then land in different buckets, depending on which offset each buoy sent. That breaks the hourly aggregation and the feed built on it.
- Parsed timestamps are converted to UTC on ingest anyway (per the README), so a real reading with a −03:30 offset never reaches this function.
