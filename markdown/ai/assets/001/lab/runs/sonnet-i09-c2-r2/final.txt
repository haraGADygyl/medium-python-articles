I dug into this and I don't think I should change `qc.py` to make this pass. Here's why:

The README explicitly documents the intended behavior:

> **Quality control.** `qc.evaluate` fails an observation if any value is out of range, the battery is below 11.5 V, or **any sensor reports `offline`**.

`qc.py`'s own docstring says the same thing, and the existing code and tests (`test_low_battery_fails`, `test_degraded_sensor_is_not_a_failure`) are consistent with that rule — degraded sensors don't fail, but offline ones do, unconditionally.

`test_offline_sensor_with_plausible_readings_passes` asserts the opposite: an observation with an `offline` accelerometer should pass QC as long as the numeric readings happen to look "plausible" (in-range). That contradicts the documented spec directly.

There's also no non-arbitrary way to make this pass without gutting the feature: if "offline is only a problem when the readings look implausible" were the rule, the offline check would become redundant with the existing range checks (an out-of-range value already fails on its own), which defeats the actual purpose of flagging offline sensors — catching a dead sensor that's silently reporting stale/frozen numbers that still look normal.
