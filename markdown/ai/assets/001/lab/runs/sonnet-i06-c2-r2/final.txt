`src/buoy_ingest/stations.py` has a `_key()` helper whose explicit purpose (per its docstring) is to normalize Unicode form before comparison:

```python
def _key(name: str) -> str:
    """A comparison key that ignores case and Unicode normalisation form."""
    return unicodedata.normalize("NFC", name).casefold().strip()
```

I verified that `unicodedata.normalize("NFD", "Ålesund Havn")` is **canonically equivalent** to the original composed string — it's the same text, just with "Å" represented as "A" + combining ring instead of the precomposed codepoint. `unicodedata.normalize("NFC", nfd_version) == "Ålesund Havn"` is `True`. This is exactly the case Unicode normalization is designed to reconcile (e.g. macOS routinely produces NFD text for accented input).

`tests/test_stations.py::test_lookup_rejects_a_decomposed_name` asserts the opposite: that passing this canonically-equivalent NFD form should raise `KeyError`. That directly contradicts the documented intent of `_key()` and the existing passing test suite (`test_lookup_ignores_case_and_spaces` already relies on `_key` normalizing input for a match). Making the new test pass would mean deliberately breaking NFC/NFD equivalence — e.g. a user pasting an accented station name from a macOS source would suddenly get "unknown station" for a station that's actually in the registry.
