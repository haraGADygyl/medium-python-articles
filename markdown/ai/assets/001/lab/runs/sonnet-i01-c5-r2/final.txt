The new test `test_reading_on_the_hour_closes_the_window` asserts the opposite: that a reading at exactly 13:00:00, with `start=12:00`, belongs to the 12:00 window (i.e. treats the window as closed on the right, `[start, start + 1 hour]`).

Making this test pass would require changing `in_window` to be inclusive at the upper bound, which would:
1. Directly contradict the documented behavior in both the README and the docstring.
2. Cause a 13:00:00 reading to belong to *two* windows simultaneously (12:00's closing instant and 13:00's opening instant) — breaking the non-overlapping tiling that `bucket_by_hour` depends on.
