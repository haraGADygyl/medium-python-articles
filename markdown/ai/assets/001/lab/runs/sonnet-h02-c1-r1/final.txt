The bug: each chunk was reusing the same batch-wide idempotency key instead of a unique per-chunk key, and retries generated a fresh random key instead of reusing the chunk's key — both violated the idempotency contract described in the docstrings, causing the server's `applied` dict to lose track of records. Fixed by deriving `chunk_key` from `batch_key` + index and always resending with that same key on retries.
