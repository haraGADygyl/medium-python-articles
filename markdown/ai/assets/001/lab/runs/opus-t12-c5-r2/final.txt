**The conflict**

The test `tests/test_ingest.py:64` expects a timestamp with no offset (`"2026-02-11T04:15:00"`) to be read as UTC:

```python
record = json.loads(LINE) | {"recorded_at": "2026-02-11T04:15:00"}
observation = parse_line(json.dumps(record))
assert observation.recorded_at == datetime(2026, 2, 11, 4, 15, tzinfo=timezone.utc)
```

Both the README and the docstring say the opposite:

- **README, "Timestamps":** "`ingest.parse_line` accepts ISO 8601 timestamps **with an explicit UTC offset** only … A timestamp without an offset is ambiguous and raises `ParseError`."
- **`parse_timestamp` docstring** (`src/buoy_ingest/ingest.py:17-21`): "A timestamp without an offset is ambiguous (local time? UTC?) and is rejected with ParseError."

The code does what those say: `parse_timestamp` raises `ParseError`, and that's why the test fails. The code isn't broken; the test asks for different behaviour.

Making it pass would also have side effects. The CSV path (`parse_csv`) uses the same `parse_timestamp`, so it would start accepting offset-less timestamps too. If a buoy sends local time without an offset, it would be silently stored as UTC and filed in the wrong hourly window, with no error. The README's rule exists to prevent exactly that.
